# 本轮处理规则与已有建议的衔接

本表由实现阶段根据原始核查记录整理，供赵思嘉复核；不代替赵思嘉应交的处理表，也不表示她已批准本表。仓库原建议保留不改。

| 问题 | 原值或判断 | 实施与理由 |
| --- | --- | --- |
| 缺失 | Rating空；已有核查发现其中878条Reviews>0 | 原因未知；基线保留清洗档案、排除不完整记录参与聚类，固定规则中位数填补并保留标记。两种口径都报保留率。 |
| 缺失 | Current Ver、Android Ver、Content Rating、Type空 | 均列入质量报告；非聚类字段不为消除空值而瞎填，保留待核实。 |
| 重复 | 原始13列完全相同 | 固定规则按原始13列保留首条；新增ID与处理列不参与重复判断。 |
| 同名 | App相同但其他字段不同 | 不是经验证的同一实体；保留，单列人工复核清单。 |
| 异常/错位 | Rating=19，Category=1.9，Reviews=3.0M等连锁冲突 | 隔离整条记录，保存原值和每项错误理由，不凭猜测平移或插补修复。 |
| 合法极端值 | 大安装量/评论数、较高价格 | 不作IQR/3σ删除；数值非负且格式合法时保留，log1p减轻尺度影响。 |
| 大小格式 | 19M、201k | 统一十进制MB：19、0.201；声明k/M换算约定。 |
| 特殊状态 | Varies with device | 状态为varies；观测大小仍缺失。建模用代理填补值和标记，不能当作真实测量。 |
| 安装量 | 10,000+ | 转数值10000，并声明这是阈值下界，不是精确安装次数。 |
| 价格/日期 | $2.99；February 11, 2018 | 数值美元和ISO日期；解析失败显式报告；不改原始列。 |

对原建议的必要澄清：正文中的“Rating为空代表没被评分过”没有数据证据，本轮采用“评分未记录，原因未知”；建议中的`-1`特殊大小不直接进入聚类；模型只选白名单工具及策略，不执行其任意Python代码。
